# C-101 Aviojet — Extraction Guide

## Module Overview

The C-101 Aviojet has two distinct cockpit variants sharing a common Lua file structure:
- **C-101CC** — the combat-capable variant (HUD, optical gunsight, CC-specific radios)
- **C-101EB** — the basic trainer variant (different radios/nav, no HUD/gunsight)

Each variant has its own extractor: `extract_C101CC.py` and `extract_C101EB.py`.

## Command Table Structure

**Single flat table: `device_commands`** (no per-device tables)

All 999 buttons share one table: `device_commands.Button_N = 3000 + N` for N in 1..999.

This is unusual: most DCS modules have one command table per device (e.g. `systems_commands`, `lights_commands`). The C-101 uses a single monolithic table for everything.

- `extractCommandTables()` returns exactly 1 table: `device_commands`
- `deviceTableMap` maps all discovered devices → `device_commands`
- Deterministic mappings: 7/13 devices (the 6 un-mapped devices have no elements in the clickable data)

## Element Counts

| Variant | Total | With helper | Without helper |
|---|---|---|---|
| CC | 434 | 419 | 15 |
| EB | 388 | 388 | ~15 |

**No-helper elements in CC (15)** fall into three categories:
1. **Radio/nav frequency controls created by local functions** — `VHF_COMM_freq_MHz_pwr_control`, `VHF_COMM_freq_KHz_volume_control`, `VHF_NAV_freq_MHz_mode_control`, `VHF_NAV_freq_KHz_volume_control`, `ADF_freq_set_knob` are `local function` definitions in `C-101CC/clickabledata.lua`. Being local, they aren't captured by `installHelperTagger`'s `_G.__newindex` hook.
2. **Inline table literals** — `PNT-HUD-MS-SW-CP` and `PNT-ADF-2-RP` are raw Lua table literals, not function calls. They have no helper tag by definition.
3. **Miscellaneous** — `PNT-MIRROR`, clock knobs, ADI brightness controls — also inline tables or local functions.

All no-helper elements have correct `controlClass`, `arg`, `argValue`, `argLim`, so structural inference in the mapper handles them.

## Quirks and Workarounds

### 1. `_LAST_CLICK_SOUND_` must be pre-seeded
`Common/sounds_common.lua` starts with:
```lua
local count = _LAST_CLICK_SOUND_
```
This global must exist as a number before `sounds_common.lua` executes (called from `clickabledata_common.lua`). The runtime mocks it as `_LAST_CLICK_SOUND_ = 0`.

### 2. Helper functions live in clickabledata_common.lua, not a separate defs file
Unlike most modules, the C-101 does not have a `clickable_defs.lua`. All factory helpers (`default_button`, `default_2_position_tumb`, `multiposition_switch`, etc.) are defined at the top of `clickabledata_common.lua` itself. This does not affect extraction since `installHelperTagger` operates on `_G.__newindex` regardless of which file the definitions come from.

### 3. Duplicate key: PNT-COMMN-TB-RP in CC clickabledata
`clickabledata_common.lua` assigns `elements['PNT-COMMN-TB-RP']` for both the front seat and rear seat intercom transfer button, using the same key twice. The second assignment (rear seat) silently overwrites the first in Lua. Only the rear seat version survives in the extraction. This is a bug in the original DCS module files — noted for awareness.

### 4. ADF_freq_set_knob is a global function in CC clickabledata
Despite using the word `local` convention elsewhere, `ADF_freq_set_knob` is defined as a non-local `function ADF_freq_set_knob(...)` in the CC file. It is captured by the helper tagger and appears in 419 tagged elements.

### 5. EB mainpanel calls get_livery_setting_from_plugin
`C-101EB/mainpanel_init.lua` line 5 calls `get_livery_setting_from_plugin("C-101", "CPLocalListEB", "default")` — a DCS engine function. Both extractors mock this to return the default value, silencing the warning.

### 6. Engine-only files silently skipped
`tools.lua`, `KNEEBOARD/declare_kneeboard_device.lua`, and `PADLOCK/PADLOCK_declare.lua` are DCS engine scripts that don't exist in the aircraft's Cockpit directory. The error-tolerant dofile override silently skips them. This is expected behavior.

### 7. Variant-specific command IDs for "common" elements
Even elements that appear in `clickabledata_common.lua` (shared) use different `Button_N` IDs between CC and EB. For example, circuit breakers, engine controls, and ECS switches all have different command IDs in each variant. This is why separate extraction is required — the shared source text produces different runtime tables because `clickabledata_common.lua` dofiles the variant's own `devices.lua` midway through execution, and the command IDs appear to be assigned based on device IDs that differ per variant.

### 8. Mainpanel gauge calls are mostly commented out
`Common/mainpanel_init_common.lua` has all its `CreateGauge()` calls commented out (`--[[...]]`). The 4 gauges extracted come from the variant's `VR_config.lua`.

### 9. Localization catalog lives in CoreMods, not Mods
The C-101's Lua scripts are under `Mods\aircraft\C-101\` as expected, but its localization catalog is **not** alongside the module — it is in the `CoreMods` tree:

```
C:\Games\DCS World\CoreMods\aircraft\C-101\l10n\en\LC_MESSAGES\messages.mo
```

This is the catalog read by `loadDcsTranslations()` in both extractors. The global `dcs.mo` catalog contains no C-101 entries.

The catalog has **1397 entries** and many keys have non-trivial translations that differ significantly from what the Lua key suggests. Some examples:

| Lua key (raw) | Cockpit tooltip |
|---|---|
| `EJECTION HANDLE` | `Seat Firing Handle` |
| `EJECTION HANDLE SAFETY` | `Ejection Seat Handle Safety Pin` |
| `COMPUTER` | `Computer Push-Button` |
| `Blackout curtain` | `IFR Hood` |
| `(HOT MIC) TALK CIRCUIT BREAKER` | `HOT MIC TALK Breaker` |

Both extractors store the raw Lua key as `hintKey` and the resolved translation as `hint` (only when the two differ). Of the 434 CC elements and 388 EB elements, approximately 335 and ~305 respectively have a `hintKey` field.

## Notable Control Groups

- **Circuit breakers (LP series)** — `PNT-CB-*-LP` — modelled as 2-position tumb (`multiposition_switch` with 2 positions). There are ~20 of these for both seats.
- **VHF radio volume+frequency knobs** — multi-action controls with TUMB+TUMB+LEV class. No helper tag (local function); structural inference handles them.
- **ADF function/gain control** — likewise local-function, no helper tag.
- **Gunsight controls** (CC only) — e.g., `PNT-GS-DEPR-KNB-CP`, `PNT-HUD-MS-SW-CP` (depression, HUD mode switch)
- **Seat 1 (rear/instructor) duplicates** — many front-seat controls have exact rear-seat counterparts with `-BACK` suffix in the key name.
