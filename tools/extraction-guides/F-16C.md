### Expected unmatched command tables

- **`alt_commands`** — maps to `AAU34` (altimeter); naming mismatch, falls back to unique-name resolution.
- **`uhf_commands`** — used by both `UHF_RADIO` and `UHF_CONTROL_PANEL`; the generator will match the best candidate. If ambiguity surfaces it will need a `TABLE_ABBREV` entry or explicit override.

### Expected unmatched devices (no command table)

The following avionics/processor devices have no clickable controls or native command table:
MUX, MMC (has table), CADC, FLCC, HEARING_SENS, MIDS, MIDS_RT, ILS, STANDBY_COMPASS,
MACROS, AIHelper, KNEEBOARD, ARCADE, TACAN_CTRL_PANEL, SIDEWINDER_INTERFACE, TGP_INTERFACE,
IDM, MAP (has table), MAV_INTERFACE, HARM_INTERFACE, HTS_INTERFACE, ATP_INTERFACE,
VHF_RADIO, IFF, FM_PROXY.

(Some of the above — MMC, MAP — do have tables; they just have zero clickable elements routed through them.)

## Elements

Elements live in `clickabledata.lua`. Standard single-seat pattern — no `crew_member_access` field (unlike AH-64D).

Uses the standard helper functions from `clickable_defs.lua`:
`default_2_position_tumb`, `springloaded_2_pos_tumb`, `default_3_position_tumb`, `multiposition_switch`, `default_axis_limited`, `default_axis_limited_1_side`, `default_button`, `default_button_tumb`, `default_tumb_button`, `default_red_cover`, etc.

Some elements are defined as raw tables with `class`, `action`, `stop_action`, `arg`, etc. fields (e.g. `PTR-CDCP-TMB-FMODE-158`). The generic element extractor handles both forms.

## Text Field Extraction

Text fields come from the indicator page files. The F-16C uses a multi-level dofile chain: the top-level init file dofiles a `*_Pages_init.lua` helper that in turn sets `page_subsets` entries referring to files under the `DED_PagesPath` / equivalent `local` path variable.

Use the AH-64D-style `resolveDofileChain` helper with a local-path-variable resolver (supports patterns like `local DED_PagesPath = LockOn_Options.script_path..".../Pages/"` and later `page_subsets[X] = DED_PagesPath.."Page.lua"`).

Text field patterns used by the F-16C:

- `addStrPoly("name", ...)` — common
- `.name = "fieldName"` on `ceStringPoly` elements
- Loop-concatenated names `.name = "base"..string.format("%d", idx)` inside `for i = a, b do` loops

The shared page-scan logic in the AH-64D extractor handles all of the above and is reused as-is for F-16C.

## Gauges and Lamps

`mainpanel_init.lua` is ~300 lines. Most gauges are declared as named Lua globals (`CockpitAltitude`, `Canopy`, etc.) using `CreateGaugeLocal` — they will be picked up by the `namedGauges` lookup in the shared extractor.

F-16C has **no `Warning_Lights` / `Cabin_Lights` / `CautionLights` / `InternalLights` enum table** — so the enum-reverse-lookup fallback yields nothing. Any unnamed (anonymous) gauges will be named `gauge_arg_<N>` as a last resort, but this should be rare because F-16C's mainpanel uses almost exclusively named globals.

`mainpanel_init.lua` dofiles `VR_config.lua` and `../../Views.lua`. Our mocks of `SnapViews` and `ViewSettings` keep execution working when those files are missing or define partial tables.
