# DCS Native Control Extraction — A-10C Warthog

Module-specific extraction notes for the A-10C Warthog. Read `general.md` first for universal patterns.

## File Locations

- **Scripts directory:** `<DCS Install>/Mods/aircraft/A-10C/Cockpit/Scripts/`
- **clickabledata.lua:** `Scripts/clickabledata.lua`
- **clickable_defs.lua:** `Scripts/clickable_defs.lua`
- **devices.lua:** `Scripts/devices.lua`
- **command_defs.lua:** `Scripts/command_defs.lua`
- **device_init.lua:** `Scripts/device_init.lua`
- **mainpanel_init.lua:** `Scripts/mainpanel_init.lua`

Uses the standard `Cockpit/Scripts/` path.

## Devices

Standard `counter()` pattern in `devices.lua`.

## Command Tables

4 command tables, using a mix of Key constants and counter() patterns:

| Table | Count | Notes |
|-------|-------|-------|
| `visor_commands` | 2 | VISOR_TOGGLE, VISOR_DOWN |
| `crew_anim_commands` | 1 | LockCrewBody (not user-controllable) |
| `device_commands` | 90 | Generic Button_82..Button_N — clickable panel buttons |
| `Keys` | 361 | Named keyboard/HOTAS commands (HOTAS_CoolieRight etc.) |

The A-10C uses a two-tier naming scheme: `Keys` contains the human-readable named
commands (mapped to actions) while `device_commands` contains positional button
indices. The extractor captures both.

## Gauges and Lamps

212 entries total. Key patterns:

### Named global variables (auto-resolved)
Most gauges are defined as global variables in `mainpanel_init.lua` (e.g.
`ADI_Pitch`, `LeftEngineThrottle`, `HSI_heading`). The extractor builds a
`gaugeId → global name` map by scanning all globals for `_gaugeId` table keys,
so these get their human-readable names automatically.

### SystemsSignals caution lamps (resolved via reverse-map)
Caution/warning lamps are created via a `caution_lamp(arg, flag)` helper.
The `flag` argument is a value from the `SystemsSignals` table defined in
`mainpanel_init.lua`. The extractor builds a `SystemsSignals` reverse map
(`int → flagName`) and uses it to name any gauge whose `controller` is
`lamp_SystemsSignal`. This produces names like `flag_ANTISKID` (arg 484) instead
of `gauge_arg_484`.

71 caution/warning lamps resolved this way, covering:
- Caution light panel (args 480–527)
- AOA indexer lamps (args 540–542)
- Landing gear safe indicators (args 659–661)
- Engine fire handles (args 215–217)
- Miscellaneous (take-off trim, nosewheel steering, gun ready, etc.)

### Anonymous gauges
Any gauge not assigned to a named global and not using `lamp_SystemsSignal`
falls back to `gauge_arg_N`. These typically include internal animation helpers.

## Indicators

18 indicators total in device_init.lua; 13 have text fields (5 have no fields or
are empty). Most fields come from baked page definitions rather than dynamic
runtime text.

| Indication ID | Class | Field Count | Notes |
|---|---|---|---|
| 1 | A10C::ccMFCD | 727 | Left MFD — large page set; fields active only on current page |
| 2 | A10C::ccMFCD | 727 | Right MFD — same page set as ind.1 |
| 3 | A10C::ccCDU | 1322 | CDU scratchpad, line select keys, function labels |
| 4 | A10Common::ccDigitalClock | 19 | Clock display |
| 5 | A10C::ccHUD | 1137 | HUD symbology fields |
| 6 | A10C::ccAN_ALR69V | 137 | RWR (radar warning receiver) display |
| 7 | A10Common::ccCMSP | 5 | CMS programmer display |
| 8 | A10C::ccCMSC | 3 | CMS control panel display |
| 9 | A10Common::ccControlsIndicator_A10 | 12 | Controls position indicator |
| 10–13 | A10C::ccUHF_Radio | 23 each | Four UHF radio displays (ARC-164) |

**Important:** MFD (ind.1/2), CDU (ind.3), and HUD (ind.5) return many fields, but
only fields relevant to the *currently displayed page* will be non-empty at any
given time. Use the aggregate `ind.3` control to get all non-empty CDU fields at
once as a newline-joined string, rather than polling individual fields.

## Running the Extractor

```
python tools/extract_A10C.py
```

No `--dcs-dir` flag is needed if the default DCS install path resolves correctly.
Output goes to `config/nativeExtractions/A-10C.json`.

Then regenerate the control mapping:

```
python tools/generateControlMapping.py config/nativeExtractions/A-10C.json
```

## Known Quirks

- **No dedicated `devices.lua` device table used for control mapping** — the
  A-10C extractor maps all elements to device IDs from clickabledata element
  definitions directly. There are only 4 command tables (very flat structure
  compared to FA-18C's 36 tables).
- **`flag_VOID` and `flag_VOID1`/`flag_VOID2`** — these are placeholder entries
  in `SystemsSignals` (value 0, and two counter values). The arg slots for VOID1
  (arg 489) and VOID2 (arg 507) appear in the lamp table but have no physical
  caution light. They will appear in the mapping as `flag_VOID1` / `flag_VOID2`.
- **`SystemsSignalsNumber`** — the last entry in the `SystemsSignals` table is
  itself a counter value (not a signal). It will not conflict because the
  extractor only maps integer values found as `params[0]` of `lamp_SystemsSignal`
  gauges, and no gauge uses the `SystemsSignalsNumber` index.
