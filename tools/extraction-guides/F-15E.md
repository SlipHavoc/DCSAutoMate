# DCS Native Control Extraction — F-15E Strike Eagle

Module-specific extraction notes for the F-15E Strike Eagle. Read `general.md` first for
universal patterns.

## File Locations

- **Scripts directory:** `<DCS Install>/Mods/aircraft/F-15E/Cockpit/`
  **Note:** Unlike almost every other module, the scripts root is `Cockpit/` directly,
  NOT `Cockpit/Scripts/`. `clickabledata.lua`, `devices.lua`, etc. all sit in `Cockpit/`.
- **clickabledata.lua:** `Cockpit/clickabledata.lua`
- **clickable_defs.lua:** `Cockpit/clickable_defs.lua`
- **devices.lua:** `Cockpit/devices.lua`
- **command_defs.lua:** `Cockpit/command_defs.lua`
- **device_init.lua:** `Cockpit/device_init.lua`
- **mainpanel_init.lua:** `Cockpit/mainpanel_init.lua`
- **config.lua:** `Cockpit/config.lua`
- **sounds.lua:** `Cockpit/sounds.lua`

There is no `Cockpit/Scripts/` subdirectory — all Lua files are directly in `Cockpit/`.

## DCS Module Name

- **Install directory:** `F-15E`
- **DCS aircraft type (runtime):** `F-15ESE` (from `entry.lua`: `type = "F-15ESE"`)
- **Extraction output filename:** `config/nativeExtractions/F-15E.json`
- **Control mapping filename:** `config/controlMappings/F-15ESE.json`

Note the mismatch: the native extraction uses the install dir name (`F-15E.json`) but the
control mapping uses the DCS-reported runtime name (`F-15ESE.json`). The `moduleName` field
inside `F-15ESE.json` is set to `F-15ESE`.

## Devices

71 devices total. Standard `counter()` pattern in `devices.lua`.

One notable quirk: there is a comment discrepancy around devices 50–52. The comment in
`devices.lua` says `LANTPOD = 52`, but the actual lupa-assigned value is 51 (because
`counter()` is strictly sequential and a preceding entry was renumbered). Do not rely
on comments — use the live lupa values. The extractor is correct as-is.

22 devices appear in `clickabledata.lua` and have deterministic `deviceTableMap` entries
(derived from the access logger). The remaining 49 devices are indicator-only, input-only,
or unbound radar/EWS/HOTAS systems with no clickable elements.

## Command Tables

28 named `*_commands` tables. All use a **fixed-offset pattern** starting from
`start_command = 3000`, with each command assigned as `start_command + N` (where N is
a literal integer, not a per-table `counter()` call). This is different from modules that
use a `counter()` per command table.

There is also a large `Keys = {}` table at the very top of `command_defs.lua` containing
DCS engine key IDs. This is NOT a device command table — it defines keyboard input bindings
and must not be confused with the `*_commands` tables that follow it.

## Elements

469 clickable elements total. Both front-cockpit (FC) and rear-cockpit (RC) elements are
defined in the same `clickabledata.lua` file. Four factory-function dofiles are included at
the top of `clickabledata.lua` before element definitions begin.

Deterministic `deviceTableMap`: 22 of 71 devices resolved from the access logger.

### MFDG Paired-Button Canonical Collisions (benign)

The 7 MFD devices (IDs 34–40: `MPD_FLEFT`, `MPCD_FCENTER`, `MPD_FRIGHT`, `MPCD_RLEFT`,
`MPD_RLEFT`, `MPD_RRIGHT`, `MPCD_RRIGHT`) each have OSB (Option Select Button) bezel buttons
defined in pairs: `MFDG_button_positive` and `MFDG_button_negative`. Both point to the same
underlying command (via different argument directions). This produces **21 canonical name
collisions** during control mapping generation — one per Power/BRT/Cont button per MFD.

These collisions are benign: the generator deduplicates them correctly, keeping one control
definition per canonical name. No extractor or generator fix is needed.

### Raw Controls (309 unbound commands)

309 controls are extracted as type `raw` because their device→command-table binding could
not be resolved from the clickable elements. These come from HOTAS/radar/EWS/weapons devices
that only appear in `command_defs.lua` but have no corresponding clickable element in
`clickabledata.lua`. They are carried through to the control mapping as-is and are available
for use if the native command IDs are known.

## Missing Files (benign warnings)

The following files are referenced but do not exist in the F-15E module, generating benign
`dofile` warnings during extraction:

- `tools.lua` — referenced by `device_init.lua` (not needed for extraction)
- `Fonts/symbols_locale.lua` — referenced by mainpanel scripts
- `Fonts/fonts_cmn.lua` — referenced by mainpanel scripts
- `PADLOCK/PADLOCK_declare.lua` — referenced by `device_init.lua`

All of these are handled by the error-tolerant `dofile` override in the extractor, which
prints a warning but continues execution.

## Extractor Quirks Summary

1. **`scriptsRelPath = 'Mods/aircraft/F-15E/Cockpit'`** — Scripts are directly in `Cockpit/`,
   not in `Cockpit/Scripts/`. Both `script_path` and `common_script_path` in
   `LockOn_Options` must point to this directory.

2. **`Keys = {}` table in `command_defs.lua`** — A large legacy key-binding table at the top
   of the file. It is not a device command table and is excluded from extraction. The actual
   `*_commands` tables follow it and are extracted via the access logger normally.

3. **`start_command + N` offset pattern** — All commands use `start_command = 3000` plus a
   literal offset. There is no per-command `counter()` call. The access logger captures the
   resolved integer values, so this pattern is transparent to the extractor.

4. **Dual cockpit in one file** — Both front-cockpit (FC) and rear-cockpit (RC) elements
   are defined in a single `clickabledata.lua`. The extractor processes all 469 elements
   in one pass.

5. **MFDG geometry `dofile` errors** — `device_init.lua` dofiles MFD geometry setup files
   that reference engine globals (`GetHalfWidth`, `PosX`, etc.) not present in the mock
   environment. These fail silently via the error-tolerant dofile override. Indicator classes
   and fields are still extracted correctly.

6. **No GCBase dependency** — Unlike CH-47F, the F-15E does not depend on GCBase. No
   secondary scripts directory is needed.

7. **No `dcs.mo` translation** — Hint text in `clickabledata.lua` is plain English. No
   localization lookup is required (unlike CH-47F's `Cockpit.CH47.*` keys).

8. **Device 51 comment discrepancy** — `devices.lua` comments say `LANTPOD = 52`, but lupa
   assigns it 51 (sequential counter, no gap). The extractor uses live lupa values and is
   correct. Do not "fix" this to match the comment.

9. **`config.lua` is minimal** — Contains only `args_initial_state` entries for stick hiding;
   no module feature flags or conditional control sections.
