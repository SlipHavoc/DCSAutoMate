# DCS Native Control Extraction — Ka-50 Blackshark III

Module-specific extraction notes for the Ka-50 Blackshark III (BSIII).  Read `general.md` first for universal patterns, and `Ka-50.md` for the shared Lua pain-points — both modules share the same `Cockpit/Scripts/` source tree, so every extraction fix documented there applies here too.

## Relationship to Ka-50 Blackshark II

DCS ships two install directories — `Mods/aircraft/Ka-50/` (BSII) and `Mods/aircraft/Ka-50_3/` (BSIII).  The Lua source is nearly identical, but BSIII adds:

- Full ABRIS with upgraded moving-map software
- Datalink / data-link power switches (DLNK group)
- Some revised panel layouts on the right console

DCS BIOS used to expose them as a single shared module (`{ "Ka-50", "Ka-50_3" }`).  In DCSAutoMate they are treated as **two separate modules** with separate extraction JSON files, separate control mappings, and separate startup scripts.  `LoGetSelfData().Name` returns `"Ka-50_3"` when flying the BSIII.

## Extractor

`tools/extract_Ka50_3.py` — mirrors `extract_Ka50.py` exactly with the Scripts path and `moduleName` changed to `Ka-50_3`.  **All Lua pain-point fixes from `Ka-50.md` apply unchanged:**

1. `\%` escape-sequence sanitisation (`_sanitizeLua` with `dofile`/`loadfile` override)
2. `LockOn_Options` deep-nested magic table with arithmetic metamethods
3. `i_18n_.get_locale()` stub + top-level `LOCALIZE(s) = s` fallback
4. `encoding='utf-8'` + `ensure_ascii=False` in all JSON writes

The same set of harmless sub-page warnings fires during extraction — see `Ka-50.md §5`.

## Generator Output

Control count is essentially identical to BSII; the cockpit Lua is the same.

- **Total canonical controls:** similar to Ka-50 (~651)
- **By type:** discrete, relative, continuous, read-only in approximately the same proportions
- **positionMaps:** 11 (same as Ka-50)
- **`animated_guard_switch` covers:** 23 (same as Ka-50 — same helper-tagger logic in `extractUtils.py` applies)
- **`.action = {a, b}` dual-command rotaries:** same 5 controls as Ka-50 — detected structurally by `detectDualCommandRotary`; emitted as single-command N-position discretes

Re-run extraction only if the DCS module itself is updated.

## DCS BIOS Migration of `Ka-50 Blackshark III.py`

The BSIII startup script was converted from DCS BIOS `SCREAMING_SNAKE` names to canonical `Device.Command` names in the same session as the validator fixes (2026-04-30).  There was no dedicated name-map builder for BSIII — the conversion was done by hand using `Ka-50 Blackshark II.py` as a direct reference (the canonical names are identical between BSII and BSIII because the device IDs and element keys in the Lua are the same).

### Key module-specific differences from BSII

- **`moduleName` in `coverSet()`:** The helper embedded in startup scripts must use `'Ka-50_3'` as the module prefix in `scriptLoopUntilStart` control strings:
  ```python
  def coverSet(name, targetValue):
      fullName = f'Ka-50_3/{name}'
      pushSeqCmd(0, 'scriptLoopUntilStart', control=fullName, condition='=', value=targetValue, maxIterations=1)
      pushSeqCmd(dt, name, 1)
      pushSeqCmd(0, 'scriptLoopUntilEnd')
  ```
  See `.agent/snippets/cover-set-helper-ka50.md` for full documentation.

- **Ejection switch polarity:** Ka-50 ejection switches (`EJECT_SYS_INTERFACE.RIGHT-EMERG-SW1/2/3-PTR`) use **inverted logic**: `0 = ON (armed)`, `1 = DISABLED`. ColdStart sends value `0` to arm them; Shutdown sends value `1` to disable them. The original BSIII script had this wrong for Shutdown (was sending `0` to "disable"). Fixed during conversion.

- **EKRAN cover behaviour:** `CPT_MECH.P-CONTR-VMG-HYDRO-COVER-PTR` is an `animated_guard_switch`. During Cold Start, the cover is toggled open before the EKRAN switch, then left open (the switch is inside). During Shutdown, `coverSet(..., 1)` is called to re-open it (in case it was closed), the switch is flipped, and the cover is left open — matching the parked-aircraft state.

- **`int16()` helper:** Was present in the original BSIII script (legacy DCS BIOS convention). Removed during conversion; the one use case (SAI cage knob, 5 repeated calls) was rewritten to the canonical relative-delta value `-0.03` directly, same as BSII.

- **Duplicate blocks between ColdStart and HotStart:** Several code blocks (NAVLIGHT section, `VMS.SPEECH-INFO-AVAR-PTR`, the "Default startup done" UV26/weapons block) are identical in ColdStart and HotStart. When doing bulk name replacements via `multi_replace_string_in_file`, these cause "multiple matches found" errors. Fix: replace the HotStart block first using its unique `"Running Hot Start sequence."` anchor line, then replace the ColdStart block using its `"Running Cold Start sequence."` + `'Set collective full down.'` context.
