## Known failures and skip reasons

### Ejection handles — skip (safety / destructive)

`SYSTEMS.PNT-HN-ES-ST`, `SYSTEMS.PNT-HN-ES-ST-BACK`

Ejection seat handles. Actuating them triggers the ejection sequence.

### Emergency landing gear — skip (destructive)

`SYSTEMS.PNT-EMERGLG-LP`, `SYSTEMS.PNT-EMERGLG-LP-BACK`

Emergency gear extension. Cannot be reset without respawn.

### Landing gear override — skip (destructive)

`SYSTEMS.PNT-LG-OVR-CPR`, `SYSTEMS.PNT-LG-OVR-CPR-BACK`

Landing gear override. Similar destructive concern to emergency gear.

### IFR hood — skip (conditional)

`SYSTEMS.PNT-IFR-HOOD`

The IFR hood control is state-dependent and causes unpredictable validator
state between test runs.

### Canopy handles — skip (starts at unexpected state)

`SYSTEMS.PNT-HND-CNPY`, `SYSTEMS.PNT-HND-CNPY-BACK`

**Failure message:** `Could not normalise to state 0 (got 1.0000)`

The canopy handle arg starts at 1.0 in the hot-start mission (canopy open /
handle already pulled), so the validator cannot normalise to position 0 before
testing. Not a mapping error.

### Canopy lock — skip (state-dependent)

`SYSTEMS.PNT-LOCK-CNPY`, `SYSTEMS.PNT-LOCK-CNPY-BACK`

State-dependent on canopy position; skip to avoid interference.

### Pedal adjuster sliders — skip (requires handle held)

`SYSTEMS.PNT-RUDREG-CPD_arg311`, `SYSTEMS.PNT-RUDREG-CPD-BACK_arg1202`

**Failure message:** `pos 1: expected 1.0000, got 0.0000`

These are continuous controls for the rudder pedal length adjuster slider.
In DCS, sliding the adjuster requires holding the pull-handle (`arg1279` /
`arg1280`) throughout the movement. The validator cannot hold the handle while
sending axis commands, so the slider never moves. The mapping is correct — the
controls work fine when operated in sequence by a script or by hand.

The pull-handle controls themselves (`SYSTEMS.PNT-RUDREG-CPD_arg1279`,
`SYSTEMS.PNT-RUDREG-CPD-BACK_arg1280`) pass validation ("2 positions OK").
