## Validator bugs fixed this session (affects all modules)

Two bugs in `tools/validateControlMapping.py` were discovered and fixed while running Ka-50_3 validation:

1. **`testDiscrete` restore double-flip:** After sweeping positions, the unconditional restore send would flip `animated_guard_switch` toggle covers a second time if the sweep happened to leave them at `initialNative`. Fixed by reading the current arg before the restore and only sending if not already at the right value. See `.agent/research/testDiscrete-toggle-cover-restore-bug.md`.

2. **`testDiscretePositionMap` pos-0 false failure:** If a control's position 0 maps to the cockpit's startup-state arg (e.g. 0.0), commanding position 0 correctly does nothing — the arg was already right — but the old logic flagged it as unchanged. Fixed by conditioning the failure on `preNative` not already equaling the commanded value. See `.agent/research/testDiscretePositionMap-pos0-false-failure.md`.

## Known remaining failures (8)

### `animated_guard_switch` covers that don't fully settle (approx 5–6)

Some covers animate slowly and return a stable arg before the visual animation completes. At the default 0.3s delay, `waitForStable` occasionally times out before the arg reaches its target position. These are timing/delay issues, not mapping errors. Workaround: increase the test delay with `--delay` when validating covers specifically.

Known affected covers include some in the `EJECT_SYS_INTERFACE`, `ELEC_INTERFACE`, and `FIRE_EXTING_INTERFACE` groups — these are real covers that require the pilot to physically interact with them, and the DCS animation is intentionally slow.

### Spring-loaded / momentary controls (approx 2–3)

A small number of controls are springloaded (e.g. certain ABRIS buttons, the APU valve handle) and return to their rest position immediately after being commanded. The validator's "did the arg change" check catches the transition, but the "is it at the expected position" check fails because the arg has already snapped back. These are not mapping errors.

## Skips (133)

All 133 skips are indication/display fields (read-only `arg.N` controls) that are not emitting a value from `list_indication()` in the current cockpit state. This is normal — most indication fields are state-dependent (they only appear in specific modes or when specific systems are active). Same pattern as FA-18C, AV8BNA, Mi-24P.

## `animated_guard_switch` covers — validation behaviour

Ka-50_3 has 23 covers built by the `animated_guard_switch` helper. These are tagged during extraction (`helper = 'animated_guard_switch'`) and emitted as 2-position discretes by the generator. The validator tests them like any other discrete: command position 0, wait, check arg; command position 1, wait, check arg; restore.

Key characteristics confirmed by live testing:

- **Toggle semantics:** Any command value toggles the cover — the value itself is ignored. The validator's sweep (command 0, then 1, then restore) works correctly because the toggle alternates state on each command.
- **Restore guard required:** After sweeping, the restore send must be guarded by a read (`queryArg`) — see validator bug #1 above.
- **Position naming:** Position 0 = closed (guard down), position 1 = open (guard up), for all 23 covers tested.

## Notes on startup script validation

The `Ka-50 Blackshark III.py` startup script uses `coverSet()` helpers (via `scriptLoopUntilStart`/`scriptLoopUntilEnd`) rather than bare `pushSeqCmd` for toggle covers. This was confirmed working in live DCS during this session (Cold Start, Hot Start, Shutdown all functional). The `coverSet()` pattern makes the script idempotent regardless of the initial cover state.
